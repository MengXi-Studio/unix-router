# 小程序原生返回后路由状态陈旧（issue #7）实施方案

## 需求

GitHub issue #7：ux-router 0.8.2 + HBuilderX 5.34 + MP-WEIXIN。页面 A `push` 进入登录页后，用微信原生返回（导航栏返回 / 侧滑）回到 A，再次 `push` 登录页时被判定为重复导航，返回 `NavigationFailure { code: 16 (DUPLICATED) }`，页面不跳转。期望第二次 push 正常进入登录页，且 `currentRoute` 反映真实页面栈。

## 需求分析

- 根因确认（源码核对）：
  - `router/index.uts` 的 `install()` 中，`onShow → syncRoute()` 的全局 mixin 被包在 `#ifdef WEB` 内，小程序端仅在冷启动 `initRoute()` 同步一次；
  - 微信原生返回不经过任何 `uni.*` 路由 API，`routeState.currentRoute` 不再回写；
  - `performNavigation` 的重复检测 `isSameRouteLocation(to, from)` 直接使用陈旧的 `from` → 误判 DUPLICATED。
- 次要事实核对：issue 中「failNavigation 是 resolve 而非 reject」的描述与源码不符，`failNavigation` 实际返回已拒绝的 Promise；症状「静默无效果」源于业务侧未 catch，而非 resolve。
- 影响面：`packages/core/src/router/index.uts`（install / performNavigation / back）；双发行版镜像由 `pnpm sync:uni-modules` 同步；docs 中英关于「仅 H5 注册 mixin」的表述需同步修正；playground 无需改动；`.trae` 规则红线 7 需同步。

## 伪代码设计

1. `install()`：把 `onShow → syncRoute()` mixin 的条件编译从 `#ifdef WEB` 改为 `#ifdef WEB || MP`（小程序页面 onShow 在原生返回、tab 切换时触发，可对齐页面栈）。
2. 新增私有方法 `healRouteStateFromStack()`：读取 `history.currentStack()`，与 `routeState.currentRoute.value.path` 归一化比较；不一致则 `syncRoute()`（兜底 App 原生返回、以及 mixin 未生效的场景），异常仅告警不抛。
3. `performNavigation` / `back()`：在等待前序导航之后、读取 `from` 之前调用自愈，保证守卫入参与重复导航判定基于真实页面栈。

## 疑问清单

无（根因与修复点由源码直接确认，issue 已给出复现步骤与建议方案）。

## 实施记录

### 代码

- `packages/core/src/router/index.uts`
  - `install()`：`onShow → syncRoute()` 全局 mixin 条件编译由 `#ifdef WEB` 改为 `#ifdef WEB || MP`。
  - 新增私有方法 `healRouteStateFromStack()`：`history.currentStack().path` 与 `routeState.currentRoute.value.path` 归一化比较，不一致则 `syncRoute()`；异常仅 `warn` 不抛。
  - `back()`：等待前序导航后、读取 `from` 前调用自愈。
  - `performNavigation()`：同上，避免重复导航误判与守卫 `from` 错误。
- 镜像：`packages/playground/uni_modules/ux-router/utssdk` 已同步，`node scripts/sync-uni-modules.mjs --check` 输出「镜像一致」。
