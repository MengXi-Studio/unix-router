# @meng-xi/unix-router v0.8.3 发布：修复小程序原生返回后的重复导航误判

> v0.8.3 为 **PATCH** 版本（0.8.2 → 0.8.3），修复微信小程序端「原生返回后再次 `push` 被判定 `DUPLICATED`（code 16）」的问题。**无 API 变更、无破坏性变更**；H5 与 App 端行为不变，升级无需改动业务代码。

## 一、问题现象（issue #7）

运行环境：uni-app x + HBuilderX 5.34 + MP-WEIXIN + ux-router 0.8.2。

复现步骤：

```
页面 A —— router.push('login') ——→ 登录页
        ←—— 微信原生返回（导航栏返回 / 侧滑）

页面 A —— router.push('login') ——→ 被 reject：
        NavigationFailure { code: 16, DUPLICATED }
        页面不跳转
```

同一段 `push` 代码在 H5 端正常，因此问题此前未被发现。附带说明：issue 中曾观察到「没有任何反应」，原因是业务侧没有 `catch` 导航失败——`failNavigation` 实际返回的是**已拒绝的 Promise**，并非 resolve。

## 二、根因

### 1. 小程序端从未回写路由状态

`install()` 中负责对齐状态的全局 mixin 被包在 `#ifdef WEB` 内：

```ts
// 0.8.2 及以前
// #ifdef WEB
const router = this
app.mixin({
	onShow() {
		router.syncRoute()
	}
})
// #endif
```

小程序端只在 `createRouter` 冷启动时通过 `initRoute()` 同步过一次。微信原生返回（导航栏返回 / 侧滑）不经过任何 `uni.*` 路由 API，也就没有任何回调把 `routeState.currentRoute` 更新回 A 页——内部状态一直停留在登录页。

### 2. 重复导航检测拿到陈旧的 `from`

`performNavigation` 的重复检测：

```ts
const from = this.routeState.currentRoute.value  // 仍是登录页（陈旧）
if (isSameRouteLocation(to, from)) {             // to 也是登录页
	return fail(NavigationFailure.DUPLICATED)
}
```

于是「从 A 再次去登录页」被误判成「已经在登录页」。

## 三、修复方案（双保险）

### 1. 扩大 mixin 覆盖范围

```ts
// #ifdef WEB || MP
const router = this
app.mixin({
	onShow() {
		router.syncRoute()
	}
})
// #endif
```

H5 与微信小程序在页面每次显示时（含原生返回、侧滑、TabBar 切换）自动 `syncRoute()`。App 端维持原状：仍建议在页面 `onShow` 自行调用 `router.syncRoute()`。

### 2. 导航前按页面栈自愈

仅靠 `onShow` 仍有窗口期：从页面栈回退到 `onShow` 触发之间，若业务代码立刻发起导航，状态仍是旧的。因此新增私有方法：

```ts
private healRouteStateFromStack(): void {
	try {
		const stack = this.history.currentStack()
		if (normalizePath(stack.path) === normalizePath(this.routeState.currentRoute.value.path)) {
			return
		}
		this.syncRoute()
	} catch (e) {
		warn(`路由状态自愈失败: ${e}`)
	}
}
```

`back()` 与 `performNavigation()` 在**等待前序导航之后、读取 `from` 之前**调用它：

- 重复导航检测基于真实页面栈，不再误判；
- 守卫的 `from` 参数同样正确（此前守卫可能收到「返回前」的页面）。

App 端虽然没有 mixin，但同样受这一层保护，因此 App 冷启动、拦截器转交等场景的状态一致性也一并改善。

## 四、行为对比

| 场景 | 0.8.2 | 0.8.3 |
| --- | --- | --- |
| H5：原生返回后再次 `push` | ✅ 正常（onShow mixin 已覆盖） | ✅ 正常（不变） |
| 微信小程序：原生返回后再次 `push` | ❌ 误判 `DUPLICATED` | ✅ 正常（mixin + 自愈） |
| 微信小程序：原生返回后**立刻**导航（onShow 前） | ❌ 误判 `DUPLICATED` | ✅ 正常（自愈兜底） |
| App：原生返回后再次 `push` | ✅ 正常 | ✅ 正常（自愈兜底） |
| 守卫 `from` 参数 | 原生返回后可能为旧页面 | 始终为真实栈顶页面 |

## 七、升级指南

0.8.2 → 0.8.3 **无需改动代码**：

```bash
pnpm add @meng-xi/unix-router@0.8.3
```

使用 uni_modules 形态的工程，请到插件市场更新 `ux-router` 至 0.8.3。

**建议**：小程序工程升级后，可移除此前为绕过该问题而在页面 `onShow` 中额外添加的 `router.syncRoute()` 调用（保留也不会产生副作用）；App 端仍需保留。
