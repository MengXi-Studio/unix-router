# @meng-xi/unix-router v0.2.0 发布：守卫下沉到 uni API 层

**发布日期**：2026-09-09

unix-router v0.2.0 发布！本次升级带来两项关键改进：**uni API 拦截（opt-in）** 让守卫从「仅库内生效」下沉到 uni API 层，以及**重复导航判定优化**。

## 核心更新

### 新增：uni API 拦截（opt-in）

新增 `RouterOptions.interceptUniApi` 配置（默认关闭）。启用后，**绕过路由器、直接调用 `uni.navigateTo` / `redirectTo` / `switchTab` / `reLaunch` / `navigateBack` 的跳转也会被拦截并转入守卫链**，守卫对全量导航生效。

设计要点（借鉴 uni-router 的 interceptor 插件并适配 uni-app x）：

- **调用去重**：以计数器区分「路由器内部发起」与「外部调用」，避免守卫被二次执行
- **阻止 + 转发**：外部调用解析 uni URL → 转 `router.*` 走完整守卫链 → 阻止原始调用
- **H5 switchTab 特判**：阻止 `uni.switchTab` 会导致 H5 TabBar 组件状态卡死，故放行原调用并在成功回调中同步路由状态
- **平台版本门槛**：需 Web 4.0 / 微信 4.41 / Android 3.97 / iOS 4.11 / HarmonyOS 4.61 及以上运行时

```typescript
// 开启后，业务中直接调用 uni.navigateTo('/pages/xxx') 同样会触发守卫链
const router = createRouter({ routes, interceptUniApi: true })
```

> 注意：微信小程序端 `<navigator>` 组件跳转与点击 tabBar（底层不触发 `uni.switchTab`）无法被拦截，此场景需在页面 `onShow` 兜底守卫。

### 修复：重复导航判定优化

重复导航判定从「path + query」扩展为 **`path + query + params + hash` 全部一致才判 `DUPLICATED`**。此前携带不同 `params` 重入当前页会被误判为重复导航并报错，现已允许以新参数重入当前页刷新数据，同时仍能拦截真正无意义的重复 push。

## 安装方式

- **uni_modules（推荐）**：`import { createRouter } from '@/uni_modules/ux-router/utssdk/index.uts'`
- **npm**：`pnpm add @meng-xi/unix-router`（`packages/core` 为 UTS 源分发）

从**入门到精通**的完整文档（🟢 入门 → 🟡 进阶 → 🔴 精通）位于 `packages/docs`，`RouterOptions` 已同步 `interceptUniApi` 字段与平台兼容说明（中文 / 英文）。

## 平台兼容性

- Web / H5、微信小程序 → 编译为 JS
- App-Android → 编译为 Kotlin / JS
- iOS（VDOM）→ 编译为 Swift
- 底层仅依赖 `uni.*` 原生导航 API，双模式兼容 uni-app x
