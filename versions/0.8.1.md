# @meng-xi/unix-router v0.8.1 发布：H5 刷新返回无效修复，返回栈底自动兜底

> v0.8.1 为 **PATCH** 版本（0.8.0 → 0.8.1），修复「H5 刷新 / 冷启动直连非首页后点返回无效」的问题，并为 `back()` 增加页面栈不足时的入口页兜底。**无破坏性变更**；唯一行为变化：栈深不足时的返回由 reject `CANCELLED` 变为兜底导航（详见兼容性表）。

## 一、问题现象：刷新后返回无效

H5 端在详情页等非首页**刷新**（或直接冷启动进入深链）后，点击导航栏返回箭头无任何反应——`router.back()` 未被调用、控制台无报错，页面原地不动。

## 二、根因

uni-app x H5 框架的导航栏返回按钮逻辑（uni-h5 内部 `onPageHeadBackButton`）：

```js
function onPageHeadBackButton() {
	if (getCurrentPages().length === 1) {
		uni.reLaunch({ url: '/' })                 // 栈深 = 1：回根路径，不走 navigateBack
	} else {
		uni.navigateBack({ from: 'backbutton' })   // 栈深 > 1：会被 InterceptorPlugin 转交 router.back
	}
}
```

关键在于：**栈深 = 1 时框架调用的是 `uni.reLaunch({ url: '/' })`，而非 `uni.navigateBack`**。该调用被 InterceptorPlugin 拦截后，因根路径 `/` 不是有效页面路由被**静默丢弃**，同时原始调用被 `invoke` 返回 `false` 阻止——两道出口都被堵死，返回「无效」。

## 三、修复

两处兜底，共享同一目标：**栈深不足时，返回自动重载入口页**（路由表中首个 `meta.isTab` 路由，经 `relaunch` 执行）：

1. **拦截器根路径兜底**：外部 `reLaunch` 的 url 为根路径 `/` 时，转交 `relaunch` 到入口页（此前直接丢弃）
2. **`back()` 栈深不足兜底**：栈长 < 2 或 `delta >= 栈长` 时，由 reject `CANCELLED` 改为自动 `relaunch` 入口页（覆盖 App 端冷启动深链后无处可退的场景）

两处均经完整守卫链（`requireAuth` 等拦截仍然生效）；路由表无 tabBar 路由时，`back()` 维持 reject `CANCELLED`，拦截器忽略该调用。

浏览器实测验证：详情页刷新后点返回箭头、以及直接调用 `uni.navigateBack({ delta: 1 })`，均正确回到首页，守卫链（`beforeResolve` / `afterEach`）日志正常，无运行时报错。

## 四、版本说明

PATCH 版本（0.8.0 → 0.8.1），无 API 增删、无破坏性变更。唯一行为变化见下表：

### 版本兼容性

| 功能 | 0.8.0 | 0.8.1 |
| --- | --- | --- |
| 核心 API（push / replace / relaunch / back / 守卫 / 插件） | ✅ | ✅（不变） |
| H5 刷新 / 冷启动直连非首页后点返回箭头 | ❌ 无反应 | ✅ 兜底回入口页 |
| `back()` 栈深不足（路由表有 `isTab` 路由） | ❌ reject `CANCELLED` | ✅ 兜底 `relaunch` 入口页 |
| `back()` 栈深不足（路由表无 `isTab` 路由） | reject `CANCELLED` | reject `CANCELLED`（不变） |
| `back(delta)` App 端调用 | 需显式传参 | 需显式传参（不变，UTS 接口签名不支持默认值） |

> 提示：App 端调用返回请始终显式传参 `router.back(1)`——UTS 接口方法签名不支持默认值，省略实参将编译报错 `No value passed for parameter 'delta'`。
